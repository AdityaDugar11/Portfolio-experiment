# Multi-tile proof and dataset record

Copernicus DEM GLO-90, 2021 release, 3 arc-second nominal sampling; digital surface model, includes structures/vegetation. Source tile URL: https://copernicus-dem-90m.s3.amazonaws.com/ . Accessed 2026-11-26. License and attribution: https://registry.opendata.aws/copernicus-dem/ ; “produced using Copernicus WorldDEM-90 © DLR e.V. 2010–2014 and © Airbus Defence and Space GmbH 2014–2018 provided under COPERNICUS by the European Union and ESA; all rights reserved”. Original raw tiles are ignored in Git and are not modified.

Proof bbox: 72–74° E, 24–25° N; two source tiles, 1200 × 2400 original cells, resampled once as a single grid to 100 × 200. NoData and invalid samples cause a hard failure; nothing is filled or fabricated. A seam comparison found a 4.18 m mean source difference across the boundary versus 4.37 m for adjacent interior samples (maximum 45.22 m and 59.39 m respectively); this is a sanity check, not a formal terrain accuracy assessment. The mesh shares vertices across the tile boundary: 20,000 vertices, 19,701 faces, all face normals positive in Z (minimum 0.864). Original elevations are preserved with vertical scale 1.

Projection: spherical local equirectangular with radius 6,371,000 m, longitude scaled by cosine of central latitude; this is a metric approximation suitable only for the proof, not a geodetic UTM reprojection or precision surveying. The proof is not centered on Bikaner and is not the Rajasthan master. Source tiles are cached, validated and re-used. Partial network failures are logged in the generated manifest. Original Bikaner proof remains unchanged.

Rebuild (Pillow and NumPy already present): `python3 artifacts/rajasthan-world/scripts/fetch_multitile.py --bbox 72 24 74 25`; `python3 artifacts/rajasthan-world/scripts/mosaic_terrain.py --bbox 72 24 74 25 --samples-per-degree 100 --output artifacts/rajasthan-world/data/proof-mosaic.npz`; `flatpak run --filesystem=/home/adityadugar/Documents/Projects/Portfolio-experiment org.blender.Blender --background --factory-startup --threads 8 --python /home/adityadugar/Documents/Projects/Portfolio-experiment/artifacts/rajasthan-world/scripts/build_multitile.py`.

Blender Flatpak 5.1.1 on Fedora f44 reports its OpenColorIO 2.5 config incompatible with runtime library 2.4.2, and falls back to disabled color management. No system files were changed. NVIDIA driver 620.73.04 reports RTX 5060 Laptop 8 GiB, but Blender CUDA lists only CPU and its OptiX backend is unavailable. Cycles CPU proof render was 2.81 s at 960 × 600, eight samples, eight threads; Eevee rendered a 96 × 60 test in 17.65 s in the headless environment. Memory usage was not measured per process. No physical or final visual quality claims are made.

A 48-tile regional proof was also built for 69–77° E, 24–30° N: 800 × 600 vertices (480,000 vertices, 478,601 faces), vertical scale 1, 14 MiB Blender scene, 3.31 s Cycles CPU render at 960 × 600 and eight samples. Mosaic generation peaked at 594,000 KiB RSS; Blender subprocess memory was not captured by the Flatpak wrapper. This extent covers the proposed forts but excludes parts of Rajasthan; it is not a complete master. An expanded 69–78° E, 23–31° N acquisition timed out on 23 tiles after bounded retries. The generated cache manifest records missing files; retry the same command to resume. No master scene is claimed.

The mosaic tool currently supports integer-degree north/east bounding boxes with uniform tile shapes and fails if NoData is present; it does not interpolate missing data. The local projection is approximate and uses a fixed central-latitude longitude scale, so distortion grows over the regional extent. Accurate reprojection, fortified destination verification, sampled fort locations, full terrain extent, natural materials, a polished horizon and improved color management remain outstanding. No fort architecture has been created.
