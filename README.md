# The Living Signal — Aditya Dugar

A cinematic, scroll-driven personal portfolio built around a ten-chapter story of curiosity, software engineering, intelligent systems, experimentation, collaboration, and creative technology.

## Read before making changes

This repository is documentation-first. The project source of truth is:

1. [`AGENTS.md`](AGENTS.md) — mandatory instructions for every coding agent.
2. [`docs/PROJECT_BRIEF.md`](docs/PROJECT_BRIEF.md) — identity, goals, audience and constraints.
3. [`docs/DESIGN_DECISIONS.md`](docs/DESIGN_DECISIONS.md) — approved visual direction and rejected approaches.
4. [`docs/STORY_CONTENT.md`](docs/STORY_CONTENT.md) — complete ten-chapter narrative.
5. [`docs/ACT_01_SPEC.md`](docs/ACT_01_SPEC.md) — detailed opening chapter specification.
6. [`docs/TECHNICAL_ARCHITECTURE.md`](docs/TECHNICAL_ARCHITECTURE.md) — engineering and performance principles.
7. [`docs/AUDIO_DECISION.md`](docs/AUDIO_DECISION.md) — audio is disabled until a track is selected.
8. [`docs/IMPLEMENTATION_PLAN.md`](docs/IMPLEMENTATION_PLAN.md) — staged delivery and approval gates.
9. [`docs/QA_CHECKLIST.md`](docs/QA_CHECKLIST.md) — browser-level acceptance checks.
10. [`docs/REFERENCES_AND_ASSETS.md`](docs/REFERENCES_AND_ASSETS.md) — visual references and asset handling.
11. [`docs/RECORDING_REVIEW.md`](docs/RECORDING_REVIEW.md) — problems observed in the latest failed implementation.

## Important workflow

Do not delete the previous experiment to use this project. Keep it as a backup. Clone the new GitHub repository into a separate, new directory, copy these documentation files into that clone, and only then ask the coding agent to inspect and plan the project.

Do not scaffold or implement the website until the agent has read these documents, inspected the available source assets and provided an implementation plan for approval.
